# Cross-run Confirmation

| Study tier              | Exact requirements                                                                                                                                                                                                      |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Exploratory             | No qualifying supported original                                                                                                                                                                                        |
| Supported               | Signed preregistered original; verified signed manifests; configured confirmation depth; positive conservative interval                                                                                                 |
| Validated               | Supported plus a signed distinct validation dataset/pack/run, pre-execution signed plan tied to the parent finding/report, compatible target/method, and a positive conservative interval                               |
| Confirmed               | Validated plus a separate signed sealed-holdout artifact, custodian-authorized certificate, confirmatory execution, distinct dataset, valid chronology, and positive conservative interval                              |
| Independently confirmed | Confirmed plus a separate independent-evaluator run/result, authorized certificate, signed attributable independence declaration, different organization, independently controlled dataset, and no unresolved conflicts |

Every stage passes independently. A huge original cannot overpower a failed or inconclusive replication. Same-organization work is never labeled independently confirmed. Cross-version generalization is explicitly labeled and cannot masquerade as exact-snapshot replication.

## v2.2.6 promotion boundary

Study import and synthesis only promote current runs whose signed eligibility decision verifies as preregistered + fixed + pairwise + ensemble observed judging + one replication family. Adaptive, Cartesian, heuristic-only, multi-family, and every artifact before v2.2.3 remain verifiable as applicable but are rejected from new supported, validated, confirmed, and independently confirmed promotion decisions.

Sealed confirmation imports a custodian-signed disclosure-safe holdout attestation with `pack = undefined`. The main lab verifies the replication plan's pack commitment against the attestation plaintext commitment and verifies the attestation artifact hash through the request, pre-execution plan, result ledger, completed run, and study link; it never receives the plaintext holdout contents.

Chronology is `parent report signed <= plan signed <= manifest locked <= execution started <= run finished <= completed artifact signed`. Plans bind study, parent finding digest, replication key, outcome, target policy, dataset role/split, depth, analysis, desired tier, pack commitment, judge protocol, conflicts, and methodology hash.

Independence uses signed artifact, pack, dataset, and trial-ledger identities. Identical response text alone is not overlap.

# v2.2 promotion gate

Original and replication evidence must pass canonical identity verification and execution-ledger reconciliation. Exact target policies cannot promote evidence whose judge identity is only requester-supplied (`requested_only`).

### v2.2.2 promotion requirements

Every contributing run, including original development evidence, must pass canonical protocol and identity verification, signed-plan chronology, independent trial-ledger reconciliation, and judge identity checks. Missing or `unknown` judge identity blocks exact-snapshot promotion; requested-only identity is accepted only when the frozen compatibility policy explicitly permits it.
